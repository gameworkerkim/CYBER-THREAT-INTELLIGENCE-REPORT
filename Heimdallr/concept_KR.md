# Heimdallr (헤임달) — 기본 컨셉

> LLM 멀티 에이전트 자율 모의 침투 테스트 + 사이버 보안 지식 축적 시스템
> ARTEX 컨셉을 계승한 **방어 중심 · 권한 검증 기반** SaaS (Node.js + Neon + Cloudflare 프리티어)

---

> ## 🚨 보안·오남용 경고 — 반드시 먼저 읽어 주세요
>
> Heimdallr 는 ARTEX 와 마찬가지로 **LLM 이 스스로 정찰·침투·자료 반출까지 수행할 수 있는 강력한 자율 공격 도구**입니다. 이 프로젝트의 목적은 **공격을 돕는 것이 아니라**, 자율 AI 공격의 작동 원리를 이해하고 **탐지·차단·방어 역량**을 키우는 데 있습니다.
>
> - **허가 없는 사용은 범죄입니다.** 자신이 소유하거나 서면으로 명시적 허가를 받은 대상이 아니라면 어떤 시스템에도 스캐닝·탐지·익스플로잇을 실행하지 마십시오. 대한민국에서 권한 없이 정보통신망에 침입하는 행위는 **「정보통신망 이용촉진 및 정보보호 등에 관한 법률」** 위반이며, 개인정보가 결부되면 **「개인정보 보호법」** 도 적용됩니다.
> - **도메인 검증은 "소유 증명"이지 "공격 허가"가 아닙니다.** Heimdallr 의 도메인 검증 토큰은 "이 도메인을 제어하는 사람이 테스트를 요청했다"는 사실만 증명합니다. 실제 대상에 대한 테스트는 반드시 해당 자산의 소유권·운영권과 함께 법적 권한이 있어야 합니다.
> - **로컬 격리 환경 우선.** 학습·연구는 본인이 소유한 로컬 격리 환경(OWASP Juice Shop, DVWA 등)에서 수행하십시오.
>
> **모든 법적 책임과 결과는 사용자 본인이 부담합니다.**

## 1. 이름의 의미

**Heimdallr**(헤임달르/헤임달)는 북유럽 신화의 **비프로스트 다리의 수호자이자 신들의 파수꾼**입니다. 아홉 세계를 두루 보고 들을 수 있는 예민한 감각으로 신들의 영역을 지키다가, 위기가 닥치면 **걀라르호른을 불어 라그나로크의 도래를 경고**합니다.

이 이름은 이 프로젝트의 정체성을 그대로 담고 있습니다:

- **파수꾼(Watchman)** — 공격자가 아니라 **침입을 감지하고 경보를 울리는 수호자**입니다.
- **경계의 문지기** — 정당한 소유자만 통과시키는 **권한 검증 게이트**를 상징합니다(비프로스트 다리 = 도메인 검증).
- **선제적 경고** — 공격 기법을 지식으로 축적해 **미리 대비**하는 방어 중심 철학입니다.

> 즉, Heimdallr 는 "공격 도구"가 아니라 **"자율 AI 공격을 미리 알고, 검증된 주인에게만 그 실험을 허락하고, 그 결과를 방어 지식으로 환원하는 수호자"** 를 지향합니다.

## 2. 배경: ARTEX 에서 출발

Heimdallr 는 **ARTEX**(`Autumn-27/ARTEX`, AGPL-3.0)의 핵심 컨셉을 계승합니다.

| ARTEX 의 핵심 컨셉 | Heimdallr 계승 방식 |
|---|---|
| LLM 멀티 에이전트 자율 침투(planner/worker) | 동일한 멀티 에이전트 구조를 Node.js 로 재구현 |
| 이중 그래프(자산 그래프 + 탐색 그래프) | 지식·자산·탐색을 그래프로 구조화 |
| 사람-개입(human-in-the-loop) 대화 | 대시보드에서 실시간 개입 |
| 리포트 생성 | 옵션 기반 보고서 내보내기(마크다운/PDF/CSV) |
| 방어·탐지 자료(Sigma/Suricata/MISP) | **CyberSecurityWiki** 로 확장 |

ARTEX 가 "로컬에 설치해 쓰는 자율 침투 프레임워크"라면, Heimdallr 는 이를 **"아무나 바로 쓸 수 있는 웹 SaaS"** 로 바꾸되, 남용을 막는 **도메인 소유권 검증 + 24시간 제한** 장치를 씌우고, 산출물을 **재사용 가능한 지식(Wiki)** 으로 축적하는 데 초점을 둡니다.

---

## 3. 핵심 원칙 (3대 지향)

1. **방어 중심(Defense-first)** — 공격 능력을 파는 도구가 아니라, 방어자가 자율 AI 공격을 이해·탐지·차단하도록 돕는 도구.
2. **권한 검증(Authorization-first)** — "도메인 소유권 증명 + 도메인 기반 이메일 + 24시간 한정" 으로 정당한 소유자만 테스트를 요청하도록 강제.
3. **지식 축적(Knowledge-first)** — 한 번 수행한 테스트의 기법·노하우·탐지 규칙을 **CyberSecurityWiki** 에 축적해 다른 LLM/MCP 가 재사용.

## 4. 시스템 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│  프런트엔드 · API (Cloudflare Pages + Workers, Node.js/Next.js) │
│    대시보드 · 도메인 검증 · LLM 키 관리 · 보고서 · Wiki UI     │
└──────────────┬──────────────────────────────────────────────┘
               │
   ┌───────────┴───────────────┐
   │  Control Plane (Worker)   │
   │  인증 · 권한 · 스케줄링     │
   └───────────┬───────────────┘
               │
   ┌───────────┴─────────────────────────────┐
   │  Agent Runtime (step 기반, Queue + DO)    │
   │  planner · worker · mainagent (멀티 에이전트)│
   └───┬──────────────────┬──────────────────┘
       │                  │
┌──────┴──────┐   ┌───────┴─────────┐
│  Neon        │   │  Cloudflare 저장  │
│  PostgreSQL  │   │  KV / D1 / R2    │
│  (자산·탐색·  │   │  (토큰·세션·보고서)│
│   Wiki 지식)  │   └─────────────────┘
└──────────────┘
        ▲
        │ MCP / llms.txt (외부 LLM 참조)
   CyberSecurityWiki
```

| 계층 | 역할 | 기술 |
|---|---|---|
| 프런트엔드/API | 대시보드·검증·보고서 | Next.js (Cloudflare Pages/Workers) |
| Control Plane | 인증·권한·작업 스케줄 | Cloudflare Workers + Durable Objects |
| Agent Runtime | planner/worker/mainagent 멀티 에이전트 | Cloudflare Queues + Durable Objects(step 실행) |
| 데이터베이스 | 자산·탐색·Wiki 지식 그래프 | **Neon** (serverless PostgreSQL, Hyperdrive 연결) |
| 보조 저장 | 검증 토큰·세션·보고서 파일 | Cloudflare KV / D1 / R2 |
| 지식 배포 | 외부 LLM·MCP 참조 | `llms.txt` + MCP server + REST |

## 5. 핵심 기능

### 5-1. BYOK 대시보드 (Bring Your Own Key)

- 사용자가 **자신의 LLM API 키**를 입력(Anthropic/OpenAI/OpenAI 호환 엔드포인트) → 서버는 키를 **암호화 저장**하고, 대시보드는 이 키로 에이전트를 구동.
- **키는 서버가 소유하지 않는다**는 것이 원칙: 서버리스 + BYOK 구조로 **토큰 비용 부담은 사용자**, 플랫폼은 컴퓨팅만 제공.
- 다국어(한국어·영어·중국어·일본어) UI.

### 5-2. 도메인 소유권 검증 (난독화 토큰 + 24시간)

테스트를 요청하려면 대상 도메인을 **내가 실제로 제어한다**는 것을 증명해야 합니다.

1. **난독화 토큰 발급** — Heimdallr 가 무작위/난독화 텍스트를 생성.
2. **서브 디렉터리 삽입** — 사용자가 그 텍스트를 해당 도메인의 서브 디렉터리(예: `https://domain/.well-known/heimdallr/<token>`)에 배치.
3. **검증** — Heimdallr 가 HTTP 로 해당 경로를 확인해 일치 여부 판정(Google Search Console / Let's Encrypt HTTP-01 방식과 유사).
4. **24시간 한정 권한** — 검증 성공 시 **24시간 동안만** 그 도메인(및 등록된 범위)에 대해 모의 테스트 허용. 만료 시 재검증 필요.

> **도메인 기반 이메일 요구:** 요청자는 대상 도메인에 소속된 이메일(예: `admin@domain.com`)이 있어야 합니다. **무료 이메일(gmail.com·naver.com·daum.net·kakao.com 등)은 테스트 대상 도메인으로 사용할 수 없습니다.** 이는 "내 도메인 + 내 도메인 메일"이라는 **이중 소유 신호**를 강제해 남용을 차단하기 위함입니다.

### 5-3. LLM 멀티 에이전트 모의 침투

- ARTEX 의 planner/worker/mainagent 구조를 Node.js 로 재구현.
- 검증된 도메인/범위 안에서 자율 정찰 → 취약점 탐색 → 결과를 그래프에 축적.
- Cloudflare 프리티어 CPU 제한 때문에 에이전트는 **한 번에 끝내지 않고 step 단위로 분할**(Queue + Durable Objects)해 실행.

### 5-4. CyberSecurityWiki (지식 축적)

- 수행한 테스트의 **기법·노하우·탐지 규칙·대응법**을 구조화된 위키로 축적.
- **다른 LLM·MCP 가 참조**할 수 있도록 `llms.txt` + MCP server + REST API 제공.
- 상세는 `cybersecurity-wiki.md` 참조.

### 5-5. 보고서 내보내기 (옵션)

- 테스트 완료 후 **마크다운 / PDF / CSV(취약점 목록)** 형태로 보고서 내보내기.
- 탐지 규칙(Sigma)과 하드닝 체크리스트를 함께 포함하는 **방어자용 보고서** 옵션.

## 6. 기술 스택

| 구분 | 선택 | 이유 |
|---|---|---|
| 언어 | **Node.js (TypeScript)** | Cloudflare 에지 네이티브, MCP/LLM 생태계 풍부 |
| 프런트엔드/API | **Next.js** (Cloudflare Pages + Workers) | 단일 코드베이스, 정적+API 통합 |
| 데이터베이스 | **Neon** (serverless PostgreSQL) | 프리티어 존재, Cloudflare Hyperdrive 로 TCP 연결 |
| 보조 저장 | Cloudflare KV / D1 / R2 | 토큰·세션·보고서 등 무상태 데이터 |
| 에이전트 실행 | Cloudflare Queues + Durable Objects | 프리티어 CPU 제한 내 step 기반 실행 |
| 지식 배포 | `llms.txt` + MCP server + REST | 외부 LLM 참조 용이 |

## 8. 라이선스와 법적 고지

- ARTEX(원본)의 AGPL-3.0 정신을 이어 **AGPL-3.0** 또는 이와 양립하는 라이선스 검토(최종 라이선스는 구현 시 확정).
- 도메인 검증은 "소유 증명"일 뿐, **실제 대상 테스트의 법적 권한을 보장하지 않습니다.** 소유권·운영권·계약에 따른 명시적 권한이 별도로 필요합니다.
- 모든 법적 책임과 결과는 사용자 본인이 부담합니다.
