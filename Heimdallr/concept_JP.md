> LLM マルチエージェント自律型ペネトレーションテスト + サイバーセキュリティ知識蓄積システム
> ARTEX のコンセプトを継承した**防御優先・権限検証型** SaaS（Node.js + Neon + Cloudflare 無料枠）

## 1. 名前の意味

**Heimdallr**（ヘイムダル）は北欧神話において、ビフレスト橋を守り、神々の国を見張る**門番の神**です。九つの世界に生える草の音さえ聞き分ける鋭敏な感覚で神域を守り、危機が迫れば**ギャラルホルンを吹き鳴らしてラグナロクの到来を警告**します。

この名前は本プロジェクトの本質をそのまま表しています。

- **見張り番（Watchman）** — 攻撃者ではなく、**侵入を検知して警報を鳴らす守護者**。
- **門番** — 正当な所有者だけを通す**権限検証ゲート**の象徴（ビフレスト橋 ＝ ドメイン検証）。
- **先回りの警告** — 攻撃手法を知識として蓄積し、**事前に備える**防御優先の思想。

> すなわち Heimdallr は「攻撃ツール」ではなく、**「自律 AI 攻撃を事前に学び、検証済みの所有者にのみ実験を許可し、その結果を防御知識として還元する守護者」** を目指します。

## 2. 背景：ARTEX から出発

Heimdallr は **ARTEX**（`Autumn-27/ARTEX`、AGPL-3.0）の核となるコンセプトを継承します。

| ARTEX の核となるコンセプト | Heimdallr の継承方法 |
|---|---|
| LLM マルチエージェント自律ペネトレーション（planner/worker） | 同一のマルチエージェント構造を Node.js で再実装 |
| 二重グラフ（資産グラフ + 探索グラフ） | 知識・資産・探索をグラフとして構造化 |
| ヒューマンインザループ（human-in-the-loop）対話 | ダッシュボードでリアルタイム介入 |
| レポート生成 | オプションのレポート出力（Markdown/PDF/CSV） |
| 防御・検知アセット（Sigma/Suricata/MISP） | **CyberSecurityWiki** へ拡張 |

ARTEX が「ローカルに導入して使う自律ペネトレーションフレームワーク」であるのに対し、Heimdallr はそれを**「誰でもすぐ使える Web SaaS」** に変え、悪用を防ぐ**ドメイン所有権検証 + 24 時間制限**を組み込み、成果を**再利用可能な知識（Wiki）** として蓄積することに焦点を当てます。

---

## 3. 核となる原則（3 つの方向性）

1. **防御優先（Defense-first）** — 攻撃能力を売る道具ではなく、防御者が自律 AI 攻撃を理解・検知・遮断できるよう支援する道具。
2. **権限検証（Authorization-first）** — 「ドメイン所有権の証明 + ドメイン基準メール + 24 時間限定」で、正当な所有者のみがテストを依頼できるよう強制。
3. **知識蓄積（Knowledge-first）** — 実施したテストの手法・ノウハウ・検知ルールを **CyberSecurityWiki** に蓄積し、他の LLM/MCP が再利用。

   ┌───────────┴─────────────────────────────┐

   │  planner · worker · mainagent             │
   └───┬──────────────────┬──────────────────┘
       │                  │
┌──────┴──────┐   ┌───────┴─────────┐
│  Neon        │   │  Cloudflare      │
│  PostgreSQL  │   │  KV / D1 / R2    │

        ▲

| 層 | 役割 | 技術 |
|---|---|---|
| フロントエンド/API | ダッシュボード・検証・レポート | Next.js（Cloudflare Pages/Workers） |

## 5. 主要機能

### 5-1. BYOK ダッシュボード（Bring Your Own Key）

- 利用者が**自身の LLM API キー**を入力（Anthropic/OpenAI/OpenAI 互換エンドポイント）→ サーバーはキーを**暗号化保存**し、ダッシュボードはそのキーでエージェントを駆動。
- 原則：**プラットフォームはキーを所有しない。** サーバーレス + BYOK により**トークン費用は利用者負担**、プラットフォームはコンピュートのみ提供。
- 多言語（韓国語・英語・中国語・日本語）UI。

### 5-2. ドメイン所有権検証（難読化トークン + 24 時間）

テストを依頼するには、対象ドメインを**実際に管理していること**を証明する必要があります。

1. **難読化トークン発行** — Heimdallr がランダム/難読化テキストを生成。
2. **サブディレクトリに配置** — 利用者がそのテキストを対象ドメインのサブディレクトリ（例：`https://domain/.well-known/heimdallr/<token>`）に配置。
3. **検証** — Heimdallr が HTTP でそのパスを取得し一致を判定（Google Search Console / Let's Encrypt HTTP-01 方式に類似）。
4. **24 時間限定の権限** — 検証成功時、**24 時間のみ**そのドメイン（および登録範囲）に対するテストを許可。期限後は再検証が必要。

> **ドメイン基準メールの要件：** 依頼者は対象ドメインに属するメール（例：`admin@domain.com`）を持つ必要があります。**フリーメールドメイン（gmail.com・naver.com・daum.net・kakao.com など）はテスト対象ドメインとして使用できません。** これは「自分のドメイン + 自分のドメインメール」という二重の所有シグナルを強制し、悪用を防ぐためです。

### 5-3. LLM マルチエージェントペネトレーションテスト

- ARTEX の planner/worker/mainagent 構造を Node.js で再実装。
- 検証済みドメイン/範囲内で自律的に偵察 → 脆弱性探索 → 結果をグラフへ蓄積。
- Cloudflare 無料枠の CPU 制限のため、エージェントは**ステップ単位で分割実行**（Queues + Durable Objects）。

### 5-4. CyberSecurityWiki（知識蓄積）

- 実施したテストの**手法・ノウハウ・検知ルール・対処法**を構造化された Wiki として蓄積。
- **他の LLM/MCP が参照**できるよう `llms.txt` + MCP server + REST API を提供。
- 詳細は `cybersecurity-wiki.md` を参照。

### 5-5. レポート出力（オプション）

- テスト完了後、**Markdown / PDF / CSV（脆弱性一覧）** でレポート出力。
- 検知ルール（Sigma）とハードニングチェックリストを含む**防御者向けレポート**オプション。

## 6. 技術スタック

| 区分 | 選択 | 理由 |
|---|---|---|
| 言語 | **Node.js（TypeScript）** | Cloudflare エッジネイティブ、MCP/LLM エコシステムが豊富 |
| フロントエンド/API | **Next.js**（Cloudflare Pages + Workers） | 単一コードベース、静的 + API を統合 |
| データベース | **Neon**（サーバーレス PostgreSQL） | 無料枠あり、Cloudflare Hyperdrive で TCP 接続 |
| 補助ストレージ | Cloudflare KV / D1 / R2 | トークン・セッション・レポート等のステートレスデータ |
| エージェント実行 | Cloudflare Queues + Durable Objects | 無料枠 CPU 制限内でのステップ実行 |
| 知識配信 | `llms.txt` + MCP server + REST | 外部 LLM が参照しやすい |

## 7. 悪用防止のガードレール

| ガードレール | 説明 |
|---|---|
| ドメイン所有権検証 | サブディレクトリの難読化トークン確認 |

| 監査ログ | すべての実行・リクエストを記録 |
| 防御優先の出力 | 結果を検知ルール・ハードニングに還元 |
