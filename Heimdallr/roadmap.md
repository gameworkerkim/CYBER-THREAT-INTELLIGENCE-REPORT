# Heimdallr — 개발 로드맵

> ARTEX 컨셉을 계승한 방어 중심 자율 모의 침투 + CyberSecurityWiki 시스템의 **순차 개발 계획**
> 상태 표기: `[ ]` 미착수 · `[~]` 진행 중 · `[x]` 완료

---

## 개발 순서 요약

```
Phase 1 ──▶ Phase 2 ──▶ Phase 3 ──▶ Phase 4 ──▶ Phase 5
스캐폴드     에이전트     Wiki        보고서       다국어·배포
+대시보드   +Neon 그래프 +지식 축적   +탐지 규칙    최적화
```

- **의존성**: Phase 2 는 Phase 1 의 도메인 검증/키 관리 위에, Phase 3 은 Phase 2 의 에이전트 산출물 위에, Phase 4 는 Phase 2·3 의 결과 위에 얹힙니다.
- **원칙**: 매 Phase 끝에 "동작하는 것"을 남긴다(점진적 MVP). 방어 우선 가드레일은 1.4 에서부터 강제.

---

## Phase 1 — 스캐폴드 + 대시보드 MVP

> 목표: 브라우저에서 "LLM 키를 넣고, 도메인을 검증하는" 최소 웹 앱이 동작한다.

| # | 작업 | 산출물 | 완료 기준(DoD) |
|---|---|---|---|
| 1.1 | 프로젝트 스캐폴드 | Next.js(Cloudflare) 초기 구조, 린트·타입체크 | `npm run dev` 로 로컬 기동, 빌드 통과 |
| 1.2 | 인증 | 회원가입/로그인(JWT) | 세션 유지·로그아웃 동작 |
| 1.3 | LLM 키 관리(BYOK) | 키 입력·암호화 저장·공급자 설정 | 키 암호화 저장·평문 미노출·목록 표시 |
| 1.4 | 도메인 검증 | 난독화 토큰 발급·배치·검증·24h | 검증 성공/실패/만료 플로우 동작, 무료 이메일 도메인 거부 |
| 1.5 | i18n | 한·영·중·일 라우팅 | 언어 전환 동작 |

## Phase 2 — 멀티 에이전트 런타임 + Neon 그래프

> 목표: 검증된 범위에서 LLM 멀티 에이전트가 자율 모의 테스트를 수행한다.

| # | 작업 | 산출물 | DoD |
|---|---|---|---|
| 2.1 | Neon 스키마 | 자산·탐색 그래프 테이블(멱등 마이그레이션) | 스키마 적용·조회 동작 |
| 2.2 | Agent Runtime | planner/worker/mainagent (step 실행, Queue+DO) | 로컬 취약 앱 대상 1회 왕복 실행 |
| 2.3 | 도구·인터셉트 승인 | Bash/HTTP 도구 + 위험 호출 승인 게이트 | 승인/거부가 실행에 반영 |
| 2.4 | 실시간 관찰 | SSE 활동 스트림 + 탐색/자산 그래프 UI | 대시보드에서 진행 실시간 표시 |

## Phase 3 — CyberSecurityWiki + 지식 축적

> 목표: 에이전트 산출물이 재사용 가능한 방어 지식으로 축적되고 외부 LLM 이 참조한다.

| # | 작업 | 산출물 | DoD |
|---|---|---|---|
| 3.1 | Wiki 스키마/CRUD | Neon 위키 엔트리 + API | 엔트리 생성·조회 동작 |
| 3.2 | `llms.txt` + 공개 페이지 | 루트/카테고리 `llms.txt`, 정적 스냅샷 | LLM 이 표준 형식으로 수집 가능 |
| 3.3 | MCP server | 검색/조회 도구 | Claude 등이 도구로 호출 가능 |
| 3.4 | 수집·정제 파이프라인 | finding → 위키 후보 자동 추출(방어 우선 정제) | 실행 산출물이 위키로 자동 등록 |

## Phase 4 — 보고서 + 탐지 규칙

> 목표: 테스트 결과를 보고서로 내보내고 탐지 규칙으로 환원한다.

| # | 작업 | 산출물 | DoD |
|---|---|---|---|
| 4.1 | 보고서 내보내기 | Markdown/PDF/CSV | 파일 생성·다운로드 동작 |
| 4.2 | 방어자 보고서 | 탐지 규칙(Sigma)·하드닝 체크리스트 포함 | 규칙·체크리스트가 보고서에 포함 |
| 4.3 | ATT&CK/Sigma/MISP 연동 | 매핑·변환·내보내기 | 표준 포맷 산출 |

## Phase 5 — 다국어 완성 + 프리티어 배포 최적화

> 목표: 다국어 품질을 올리고 프리티어 한도 안에서 안정 배포한다.

| # | 작업 | 산출물 | DoD |
|---|---|---|---|
| 5.1 | i18n 완성 | 전 화면·산출물 다국어 | 4개 언어 품질 확보 |
| 5.2 | 프리티어 최적화 | 리소스 한도 점검·캐시 | 무료 한도 내 정상 운영 |
| 5.3 | 배포·운영 | CI/CD, 로그, 모니터링 | 안정 배포 |
