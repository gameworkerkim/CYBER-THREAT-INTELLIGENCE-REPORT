> LLM 多智能体自主渗透测试 + 网络安全知识积累系统
> 继承 ARTEX 理念的**防御优先 · 授权验证型** SaaS（Node.js + Neon + Cloudflare 免费层）

## 1. 名称由来

**Heimdallr**（海姆达尔）是北欧神话中守护彩虹桥（Bifröst）、守望众神国度的守护神。他感官敏锐，能听见九界之中青草生长的声音，当危险来临时，他会吹响**加拉尔号角（Gjallarhorn）**，向诸神警示诸神黄昏的降临。

这一名称正是本项目的写照：

- **守望者**——不是攻击者，而是**检测入侵、拉响警报的守护者**。
- **守门人**——象征只有合法主人才能通过的**授权之门**（彩虹桥 = 域名验证）。
- **主动预警**——将攻击知识提前积累、**未雨绸缪**的防御优先哲学。

> 简而言之，Heimdallr 不是"攻击工具"，而是一位**"提前掌握自主 AI 攻击、只向已验证的主人开放实验、并将结果回馈为防御知识的守护者"**。

## 2. 背景：源自 ARTEX

Heimdallr 继承了 **ARTEX**（`Autumn-27/ARTEX`，AGPL-3.0）的核心理念。

| ARTEX 核心理念 | Heimdallr 的继承方式 |
|---|---|
| LLM 多智能体自主渗透（planner/worker） | 以 Node.js 重新实现相同的多智能体结构 |
| 双图结构（资产图 + 探索图） | 将知识 / 资产 / 探索以图结构组织 |
| 人在环路（human-in-the-loop）对话 | 通过仪表盘实时介入 |
| 报告生成 | 可选报告导出（Markdown/PDF/CSV） |
| 防御与检测资产（Sigma/Suricata/MISP） | 扩展为 **CyberSecurityWiki** |

如果说 ARTEX 是"本地安装使用的自主渗透框架"，那么 Heimdallr 就是把它变成**任何人都能即刻使用的 Web SaaS**，并加上**域名所有权验证 + 24 小时限制**来防止滥用，同时聚焦于将成果积累为**可复用的知识（Wiki）**。

---

## 3. 核心原则（三大方向）

1. **防御优先**——帮助防守方理解、检测并阻断自主 AI 攻击，而非贩卖攻击能力。
2. **授权优先**——"域名所有权证明 + 域名邮箱 + 24 小时限制"，确保只有合法主人才能发起测试。
3. **知识优先**——将每次测试的手法、经验与检测规则积累到 **CyberSecurityWiki**，供其他 LLM / MCP 复用。

## 5. 核心功能

### 5-1. BYOK 仪表盘（自带密钥）

- 用户输入**自己的 LLM API 密钥**（Anthropic / OpenAI / OpenAI 兼容端点）→ 服务端**加密存储**密钥，仪表盘用该密钥驱动智能体。
- 原则：**平台不拥有您的密钥。** 无服务器 + BYOK 意味着**令牌成本由用户承担**，平台只提供算力。
- 多语言界面（韩语、英语、中文、日语）。

### 5-2. 域名所有权验证（混淆令牌 + 24 小时）

发起测试前，必须证明您**确实控制目标域名**：

1. **签发混淆令牌**——Heimdallr 生成一段随机 / 混淆文本。
2. **放入子目录**——用户将该文本放到该域名的子目录（如 `https://domain/.well-known/heimdallr/<token>`）。
3. **验证**——Heimdallr 通过 HTTP 抓取该路径并比对（类似 Google Search Console / Let's Encrypt HTTP-01）。
4. **24 小时限时授权**——验证成功后，仅允许在**24 小时内**对该域名（及已登记范围）进行测试，过期后需重新验证。

> **域名邮箱要求：**请求者必须拥有属于目标域名的邮箱（如 `admin@domain.com`）。**免费邮箱域名（gmail.com、naver.com、daum.net、kakao.com 等）不能作为测试目标。** 以此强制"我的域名 + 我的域名邮箱"双重所有权信号，防止滥用。

### 5-3. LLM 多智能体渗透

- 以 Node.js 重新实现 ARTEX 的 planner/worker/mainagent 结构。
- 在已验证的域名 / 范围内自主侦察 → 漏洞发现 → 将结果积累为图。
- 由于 Cloudflare 免费层 CPU 限制，智能体**分步执行**（Queues + Durable Objects），而非一次性长时间运行。

### 5-4. CyberSecurityWiki（知识积累）

- 将每次测试的**手法、经验、检测规则与修复方案**积累为结构化 Wiki。
- 提供 `llms.txt` + MCP server + REST API，供**其他 LLM / MCP 参考**。
- 详见 `cybersecurity-wiki.md`。

### 5-5. 报告导出（可选）

- 测试完成后，以 **Markdown / PDF / CSV（漏洞列表）** 导出报告。
- 提供**面向防守方**的报告选项，附带检测规则（Sigma）与加固清单。

## 6. 技术栈

| 领域 | 选择 | 理由 |
|---|---|---|
| 语言 | **Node.js（TypeScript）** | Cloudflare 边缘原生，MCP/LLM 生态丰富 |
| 前端 / API | **Next.js**（Cloudflare Pages + Workers） | 单一代码库，静态 + API 统一 |
| 数据库 | **Neon**（无服务器 PostgreSQL） | 有免费层，经 Cloudflare Hyperdrive 走 TCP |
| 辅助存储 | Cloudflare KV / D1 / R2 | 令牌、会话、报告等无状态数据 |
| 智能体执行 | Cloudflare Queues + Durable Objects | 在免费层 CPU 限制内分步执行 |
| 知识分发 | `llms.txt` + MCP server + REST | 便于外部 LLM 参考 |
